# Architecture

## Why a bridge is required

The provider issues short-lived signed camera sources rather than permanent
camera URLs. A direct generic-camera configuration would expire quickly and
would place a temporary capability in Home Assistant configuration or logs.

The add-on owns provider authentication and source renewal. Home Assistant sees
only stable local stream names and high-level entities.

## Components

### `md-parking-bridge` add-on

- atomically persists the provider session in its private data volume;
- discovers account cameras and barriers;
- renews temporary camera sources before expiry;
- updates stable go2rtc restreams;
- exposes an authenticated local API with secret-safe health data;
- isolates explicit barrier actions behind a kill switch, confirmation,
  per-target cooldown, and bounded persistent audit.

The go2rtc control API is container-loopback only. Its stable RTSP output is the
only media endpoint used by Home Assistant.

### `md_parking` custom integration

- pairs with the local bridge and guides SMS login when necessary;
- polls local health, camera, and barrier inventories concurrently;
- creates camera, guarded button, and connectivity entities;
- provides redacted Home Assistant diagnostics;
- dynamically adds newly discovered entities without changing existing IDs.

Provider credentials, raw identifiers, and signed media sources never enter
Home Assistant Core.

### Presentation

The integration creates a sidebar dashboard with connectivity state and a
camera/button block for each gate. Closed cards use cached JPEG previews;
opened cards use Home Assistant's native stream path at full frame rate.

The integration also creates a dedicated `/md-parking-car/car` dashboard for landscape vehicle
displays: two camera columns with each confirmed barrier control directly below
its camera.

Only layouts generated by recognized older releases are migrated. A dashboard
edited by the user is preserved.

## Video refresh contract

1. Obtain a new signed source and keep it inside the add-on process.
2. Replace the source behind the stable go2rtc stream name.
3. Refresh before the observed expiry and retry individual failures without
   blocking other cameras.
4. Keep HA entity IDs and local RTSP addresses stable across source rotations.
5. Report source age and safe failure classes without returning source URLs.

## Barrier control contract

1. Accept only a stable hashed ID from the discovered barrier inventory.
2. Require `control_enabled` and an explicit JSON confirmation.
3. Enforce an independent cooldown for each barrier.
4. Call the provider only from the control module, never from refresh code.
5. Persist only timestamp, hashed ID, and accepted/failed result.
